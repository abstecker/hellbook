Hell in a Cell: Rust Edition

Round 8: Docs

[Helo]. One missing letter, and it isn't a typo in prose. It's a broken link.

Square brackets in a doc comment are an intra-doc link. rustdoc resolves the name inside them the same way the compiler resolves a path, and there's nothing named Helo in scope. With RUSTDOCFLAGS="-D warnings", the broken_intra_doc_links lint fails the job.

This is the doc judge doing exactly what it was hired for. In most languages, a broken link in the docs is something a user finds six months later.

While we're in here

Fixing the letter is the minimum. There's a second, quieter problem: where the documentation lives. It's attached to the impl Hello block, and doc comments on an impl block get rendered deep in the type's page, under the methods, where hardly anybody reads. The description of what Hello is belongs on Hello itself, so it's the first thing on its page.

💾 src/lib.rs · L1–L1 · L13–L15 · step 010 of hellbook · diff · browse

/// The [Hello] project is a simple hello world program. It comes with two methods:
///
/// 1. `hello` - This method takes a name and returns `Hello, {name}!`.
/// 2. `hello_world` - A default method that returns `Hello, world!`.
///
/// ```
/// use worlds_simplest_kata::Hello;
///
/// let hello = Hello::hello("everyone");
/// assert_eq!("Hello, everyone!", hello);
///
/// ```
pub struct Hello;

impl Hello {
    #[must_use]
    pub fn hello(name: &str) -> String {
        format!("Hello, {name}!")
    }

    #[must_use]
    pub fn hello_world() -> String {
        Hello::hello("world")
    }
}

#[cfg(test)]
mod tests {
    use super::*;

    #[test]
    fn hello_world() {
        assert_eq!("Hello, world!", Hello::hello_world());
    }
}

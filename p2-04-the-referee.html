Hell in a Cell: Rust Edition

The Referee

You don't win this match by deciding you've won. You win when the referee raises your hand, and the referee is GitHub Actions. Every time you push, it checks out your code on a fresh machine it doesn't care about, runs the same commands it always runs, and tells you whether you're done.

It doesn't care how the code looks on your laptop. It doesn't care that it "works on my machine." That is the entire point of continuous integration.

💾 .github/workflows/CI.yaml · L1–L67 · step 002 of hellbook · diff · browse

name: CI

on:
  push:
  pull_request:

permissions:
  contents: read

env:
  RUSTFLAGS: -Dwarnings

jobs:
  test:
    name: Rust ${{matrix.rust}}
    runs-on: ubuntu-latest
    strategy:
      fail-fast: false
      matrix:
        rust: [stable, 1.85.0]
    timeout-minutes: 45
    steps:
      - uses: actions/checkout@v4
      - uses: dtolnay/rust-toolchain@master
        with:
          toolchain: ${{matrix.rust}}
      - run: cargo test --all

  clippy:
    name: Clippy
    runs-on: ubuntu-latest
    if: github.event_name != 'pull_request'
    timeout-minutes: 45
    steps:
      - uses: actions/checkout@v4
      - uses: dtolnay/rust-toolchain@master
        with:
          toolchain: stable
          components: clippy
      - run: cargo clippy -- -Dclippy::all -Dclippy::pedantic

  fmt:
    name: Fmt
    runs-on: ubuntu-latest
    if: github.event_name != 'pull_request'
    timeout-minutes: 45
    steps:
      - uses: actions/checkout@v4
      - uses: dtolnay/rust-toolchain@master
        with:
          toolchain: stable
          components: rustfmt
      - run: cargo fmt --all -- --check

  doc:
    name: Doc
    runs-on: ubuntu-latest
    timeout-minutes: 45
    steps:
      - uses: actions/checkout@v4
      - uses: dtolnay/rust-toolchain@master
        with:
          toolchain: stable
          components: rust-docs
      - run: cargo doc --no-deps --document-private-items
        env:
          RUSTDOCFLAGS: "-D warnings"

The rulebook

on: — when the referee shows up. Here, on every push and every pull_request.

env: RUSTFLAGS: -Dwarnings — set once at the top, so it applies to every job. -D warnings means deny warnings: anything the compiler would normally just grumble about becomes a hard error. Hold onto that one. It's the single most important line in this file, and it isn't set on your laptop.

jobs: — four judges, each scoring a different part of your fight. They run in parallel, on separate machines, and all four have to raise your hand:

JobCommandWhat it judges
testcargo test --allDoes it compile? Do the unit tests pass? Do the doc tests?
clippycargo clippy -- -Dclippy::all -Dclippy::pedanticIs the code idiomatic, by the pickiest standard Clippy has?
fmtcargo fmt --all -- --checkIs it formatted the way rustfmt would format it?
doccargo doc --no-deps --document-private-itemsDoes the documentation build cleanly, with every link resolving?

strategy: matrix: — the test job doesn't run once. It runs once for every entry in rust: [stable, 1.85.0]: once on the newest stable compiler, and once on 1.85.0. Two fights, same card. You have to win both.

if: — a job with an if: only runs when its condition is true. Two of the four judges have one. Read it closely, and think about who it lets in.

dtolnay/rust-toolchain — a widely used action, by David Tolnay, that installs whatever Rust toolchain you ask for, plus components like clippy and rustfmt.

The four judges, briefly

Tests. The Rubicon of builds. A team that stops keeping its tests green "because we don't have time" might as well hand its keyboards to the robots. Good unit tests are an army of regression testers, ready to descend on your code every time you push.

Clippy. No, not that Clippy. Rust's linter, and the best one in the business. Linting is static analysis that flags code the compiler accepts but a senior engineer would squint at. The kata dials it up to eleven, with pedantic and every warning denied.

Fmt. It seems trivial. Then two people on a team with different editor settings touch the same file, and every pull request turns into a three-hundred-line diff of whitespace. rustfmt settles the argument once, for everybody, forever.

Doc. Rust treats documentation as code: links are resolved, examples are compiled, and with -D warnings, a broken link breaks the build. That ends the oldest standoff in software — stakeholders demanding documentation, developers pointing out it's wrong the day it ships.

✍️ EDITOR: The Paul Oaks QA story ("RESPECT YOUR QA") from the old draft fits right after the Tests judge. So does anything you want to say about exploratory testing: unit tests only ever test what you thought of.

🥊 CORNER ADVICE: Your laptop and the referee are not running the same rules. Find every difference between them before you push.

The rest of the corner

The repository also carries a few files the fight doesn't turn on:

  • HINTS.md — the cargo commands that are your friends, and a warning: the compiler's suggestions don't always work.
  • LICENSE — the GNU GPL, version 3.
  • .gitignore — what Git should never commit.
  • .devcontainer/ — a container definition, so a GitHub Codespace can give you a working Rust setup in a browser tab.

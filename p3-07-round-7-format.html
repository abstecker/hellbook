Hell in a Cell: Rust Edition

Round 7: Format

Remember the extra space between fn and hello_world, the one we left alone back in Round 3? rustfmt didn't forget it.

The fix isn't to edit it by hand. It's to run the formatter:

$ cargo fmt --all

and let it do the edit for you:

💾 src/lib.rs · L21–L22 · step 009 of hellbook · diff · browse

pub struct Hello;

/// The [Helo] project is a simple hello world program. It comes with two methods:
///
/// 1. `hello` - This method takes a name and returns `Hello, {name}!`.
/// 2. `hello_world` - A default method that returns `Hello, world!`.
///
/// ```
/// use worlds_simplest_kata::Hello;
///
/// let hello = Hello::hello("everyone");
/// assert_eq!("Hello, everyone!", hello);
///
/// ```
impl Hello {
    #[must_use]
    pub fn hello(name: &str) -> String {
        format!("Hello, {name}!")
    }

    #[must_use]
    pub fn hello_world() -> String {
        Hello::hello("world")
    }
}

#[cfg(test)]
mod tests {
    use super::*;

    #[test]
    fn hello_world() {
        assert_eq!("Hello, world!", Hello::hello_world());
    }
}

$> git checkout step-009-r7-fmt

cargo fmt --all -- --check is the same formatter asked instead of told: it reports and fails, and changes nothing. That's what CI runs. On your machine, run the one that fixes things. Better yet, set your editor to format on save and never think about it again. The kata's .devcontainer/devcontainer.json already does: "editor.formatOnSave": true.

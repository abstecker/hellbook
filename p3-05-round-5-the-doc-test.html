Hell in a Cell: Rust Edition

Round 5: The Doc Test

The unit test passed. The doc test failed.

I love Rust's documentation tests. One of the biggest problems in keeping software healthy is keeping the documentation up to date. The code changes, everybody is in a hurry, and nobody goes back to fix the examples. Before long, developers will tell you the docs are worse than useless, and they're right.

A doc test turns the example into a test. If the example goes stale, the build goes red. You end up with documentation you know is correct, because it ran.

Here the example expected "Hello, everyone.", with a period, while hello has always ended with !. The code is right; the documentation lied. The fix goes in the doc comment:

💾 src/lib.rs · L8–L14 · step 007 of hellbook · diff · browse

pub struct Hello;

/// The [Helo] project is a simple hello world program. It comes with two methods:
///
/// 1. `hello` - This method takes a `String` and returns `Hello, {name}!`.
/// 2. `hello_world` - A default method that returns `Hello, world!`.
///
/// ```
/// use worlds_simplest_kata::Hello;
///
/// let hello = Hello::hello("everyone".to_string());
/// assert_eq!("Hello, everyone!", hello);
///
/// ```
impl Hello {
    pub fn hello(name: String) -> String {
        format!("Hello, {}!", name)
    }

    pub fn  hello_world() -> String {
        Hello::hello("world".to_string())
    }
}

#[cfg(test)]
mod tests {
    use super::*;

    #[test]
    fn hello_world() {
        assert_eq!("Hello, world!", Hello::hello_world());
    }
}

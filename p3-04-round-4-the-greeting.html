Hell in a Cell: Rust Edition

Round 4: The Greeting

The unit test finally speaks, and look at what the code actually says:

  left: "Hello, world!"
 right: "Hello,  wirld!!"

Three bugs in one string:

  1. Two spaces after the comma, courtesy of format!("Hello, {}!", name).
  2. wirld, a typo of the kind that sails straight through a code review, because reviewers read what they expect to see.
  3. Two exclamation points. hello already adds the !. hello_world passes in "wirld!", which brings its own. The caller and the callee both think punctuation is their job.

That last one is the interesting one. It's not a typo; it's a disagreement about who's responsible for what. hello owns the format — Hello, {name}! — so callers should pass a name and nothing else.

💾 src/lib.rs · L16–L22 · step 006 of hellbook · diff · browse

pub struct Hello;

/// The [Helo] project is a simple hello world program. It comes with two methods:
///
/// 1. `hello` - This method takes a `String` and returns `Hello, {name}!`.
/// 2. `hello_world` - A default method that returns `Hello, world!`.
///
/// ```
/// use worlds_simplest_kata::Hello;
///
/// let hello = Hello::hello("everyone".to_string());
/// assert_eq!("Hello, everyone.", hello);
///
/// ```
impl Hello {
    pub fn hello(name: String) -> String {
        format!("Hello, {}!", name)
    }

    pub fn  hello_world() -> String {
        Hello::hello("world".to_string())
    }
}

#[cfg(test)]
mod tests {
    use super::*;

    #[test]
    fn hello_world() {
        assert_eq!("Hello, world!", Hello::hello_world());
    }
}

💡 LESSON: When the caller and the callee both do the same job, you get it done twice. Decide who owns each responsibility, and have everyone else stay out of it.

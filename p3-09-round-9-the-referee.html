Hell in a Cell: Rust Edition

Round 9: The Referee

Every check is green. Now go back to Part II and reread the referee, the way you'd reread a contract after you've already signed it.

  clippy:
    name: Clippy
    runs-on: ubuntu-latest
    if: github.event_name != 'pull_request'

Clippy and Fmt only run when the event isn't a pull request. Open a PR, and two of the four judges leave the building. Test and Doc score the fight; the two pickiest judges never see it. A pull request with a lint error, or with a formatting mess, gets a green check mark from the referee.

That green check is the whole trap. Somebody — or something — opens a PR, sees it go green, and declares victory. The reviewer sees green and merges it. The red only shows up afterward, on main, when the push-triggered run finally invites the other two judges.

Think about who opens pull requests against a kata. Hold that thought until Part IV.

Close the loopholes

Two changes:

  1. Delete both if: lines. Every judge scores every fight, pull requests included.
  2. --all-targets on Clippy. Plain cargo clippy lints the library and the binary, but not the tests. Test code is still code: it gets read, copied, and trusted. It should meet the same bar.

Our code still passes: nothing in the test module offends Clippy. The difference is that now it's checked — and so is every PR that comes after.

💡 LESSON: The CI configuration is code, and it can have bugs like any other code. A gate that doesn't run is worse than no gate at all, because it still hands out green check marks. Audit your referee.
